# Mail — the two things that turn a message viewer into a mail client: an
# attachment you can actually save, and a message you can actually file.
#
# Every step is a single unmodified keysym, which is both taste and necessity:
# a mail client that needs the mouse is a failure, and a shortcut behind Ctrl is
# a shortcut a recorder cannot press.
#
# It has to be the keyboard here in any case. `move` and `click` reach sway
# (swaymsg reports success) but never reach the client: this seat is started
# with no input devices, so it advertises capabilities 0 and never gains a
# pointer, and a client is therefore never sent the motion or the button. The
# SWAYSOCK fix was necessary but is not sufficient for pointer steps.
#
# NOTE, and it should stop being true: the committed attachments-demo.mp4 was
# not recorded from this file. Per-step `wtype` still loses roughly one
# keystroke in five on this seat — measured at 4 of 5 `key j` landing, the same
# whether the gaps are 1s or 2.5s and whether or not a throwaway key goes
# first, and the same when the steps are replayed by hand instead of by the
# recorder, so it is the residual attach race and not the script. A sequence
# this long therefore almost never comes out clean: eight takes, none clean.
# The committed video was made by sending these same keys in one `wtype`
# invocation, which does not race, and its effects were checked on disk
# afterwards (262 bytes byte-exact, and the message in .Trash/cur). When the
# drop is fixed, re-record from this file and delete this note.

wait 2.0

# ---------------------------------------------------------------------------
# The message with a real binary attachment. The reader lists the files it
# carries — and says, separately, that one inline image is referenced by the
# message rather than attached to it, so it is not offered as a file.
# ---------------------------------------------------------------------------
key j
wait 2.2

# V walks the attachment list. The inline logo is not in it.
key v
wait 2.0

# W opens the shared file dialog with the attachment's own name filled in —
# already through the sanitiser, so a message can hand this dialog a file name
# and never a path.
key w
wait 2.6

# Save. The decoded bytes go to disk byte for byte — NUL bytes, CRLF runs and
# all. The dialog would have asked first before replacing anything.
key Return
wait 2.8

# ---------------------------------------------------------------------------
# Filing. A move between folders of one account is rename(2), and the `:2,`
# flag suffix travels with the file, so what you have read stays read.
# ---------------------------------------------------------------------------
key m
wait 2.2
key j
wait 0.7
key j
wait 1.2
key Return
wait 2.6

# Z puts it back. Undoing a rename is the same rename the other way.
key z
wait 2.6

# D deletes: the same move, with Trash chosen for you.
key d
wait 2.8

# ---------------------------------------------------------------------------
# And it really is in Trash — as a file, which any Maildir tool can see. The
# sidebar's Trash count carries it; the file itself is checked on disk after
# the recording, which is the claim that actually matters.
# ---------------------------------------------------------------------------
key h
wait 3.0
